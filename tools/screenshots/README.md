# How the screenshots were made

Every image on the site is a real capture of the running app (Chromium through Playwright, 1440x900 for desktop, 390x844 for phone), filled with sample data that these scripts create. Nothing is generated by an image model, drawn over, or edited, apart from cropping the empty lower part of a few pages (see `make-images.py`).

Each capture is made **twice**, `MODE=dark` and `MODE=light` (the colour scheme the app follows), and becomes `<name>-dark.webp` and `<name>-light.webp`. The page shows the one that matches the look the visitor chose. (Per-palette captures would be 29 palettes times 25 images, so there are two.)

## The sample data and the sample pictures
The data is invented: fictional artists and albums, a made-up household, a pretend budget. The pictures inside the apps (album covers, recipe pictures, the TurboCut clips, the trip picture in the Docs and Slides captures) are **drawn by `media.mjs`** (SVG rendered by Chromium; the clips are drawn frame by frame and joined by `ffmpeg`). They are not photographs and not made by an image model; they stand in for the photos a real library would have so the apps are not showing empty placeholders. The sandbox this was made in could not reach any photo host, which is why. If real, freely licensed photos are used later, say so on the About page and in this file.

TurboMusic's audio is a synthesised tone (`ffmpeg`, below) so tracks count as having audio.

## What you need
- Node 22, pnpm 10, `ffmpeg`, Python 3 with Pillow, and Playwright (`PLAYWRIGHT_MODULE=<path to playwright's index.mjs>` if it is not resolvable; `CHROMIUM=<binary>` to choose a browser).
- A checkout of each app next to each other, `pnpm install --ignore-scripts` in each. In a sandbox that blocks `codeload.github.com` the apps' `turbothemes` dependency (a GitHub tarball of turboengine at a pinned commit) cannot be fetched: `git fetch --depth 1 origin <sha>` in a turboengine checkout, `git archive <sha> themes | tar -x`, and point each app's `turbothemes` dependency at that folder with `file:` before installing (this was done for the captures; the app checkouts are scratch copies).

## Run the apps (each on its own port, so they can all run at once)
| App | Start | Seed | Capture |
|---|---|---|---|
| TurboBudget | `npx vite --port 5301 --host 127.0.0.1` (IPv4 explicitly if the machine has no IPv6) | in `budget.mjs` (written to `localStorage`) | `node budget.mjs` |
| TurboCut | `npx vite --port 5302` | the clips from `media.mjs` + `ffmpeg`, see below | `node cut.mjs` |
| TurboDocs | `npx vite --port 5303` in `apps/web` | typed into the editors by `docs.mjs` / `slides.mjs` (pictures from `media/keep/`) | `node docs.mjs`, `node slides.mjs` |
| TurboKeep | server: `TURBOKEEP_DATA=<dir> TURBOKEEP_ADMIN_USER=demo TURBOKEEP_ADMIN_PASSWORD=demo-password-1 npx tsx src/server.ts` in `apps/server` (port 47901), web: `npx vite --port 5304` in `apps/web` | `node seed-keep.mjs` | `node keep.mjs`, `node keep-note.mjs` |
| TurboPantry | server: `TURBOPANTRY_DATA=<dir> TURBOPANTRY_UPDATE=0 node --experimental-strip-types src/index.ts` in `packages/server` (47900), `... index.ts add-user Luka` prints a token, web: `npx vite --port 5305` in `apps/web` **with `/images` proxied to 47900 next to `/api`** (recipe pictures are served by the server) | `MEDIA=<dir> node seed-pantry.mjs <token>` | `node pantry.mjs <token>` |
| TurboMusic | server: `TURBOMUSIC_DATA_DIR=<dir> node --experimental-strip-types src/index.ts` in `packages/server` (47813, prints a token), web: `npx vite --port 5306` in `apps/web` | `MEDIA=<dir> AUDIO=<dir> node seed-music.mjs <token>` (covers from `media/covers`, tones `audio/t1.mp3` .. `t4.mp3`) | `node music.mjs <token>`, `node looks.mjs <token>` |
| TurboUI | `cargo build -p turboui-demo --release` | none | `turboui-demo --theme macos-dark/liquid --png raw/ui-demo-dark.png 1200 760`, and `--theme macos/liquid` for `ui-demo-light.png` |

`./run-all.sh dark light` runs every capture for both modes (it expects the apps to be running, the tokens in `MUSIC_TOKEN` and `PANTRY_TOKEN`, and `MEDIA`, `CUTMEDIA`, `OUT`). The captures are written to `./raw` (`OUT=<dir>` changes that). Then `python3 -I make-images.py raw ../../site/img/screens` makes the WebP files the site serves (and `site/og.png`), and `node ../../scripts/make-pages.mjs` writes the pages.

Not captured: **TurboBox** (an Android app, nothing here could run it) and **TurboMC Server** (needs Qt 6.8, which the sandbox could not download). The page simply shows no screenshot area for them (no notice, no mock-up).

## The synthetic media
```
node media.mjs      # media/covers/*.jpg, media/food/*.jpg, media/keep/*.jpg and the frames of the two clips in media/frames/
# TurboCut: join the frames and add a tone (media/morning-clip.webm 8 s, media/closing-clip.webm 6 s)
ffmpeg -framerate 15 -i media/frames/morning/%03d.jpg -f lavfi -i "sine=frequency=330:sample_rate=48000:duration=8" -vf "fps=30,format=yuv420p" -c:v libvpx-vp9 -b:v 3M -deadline realtime -cpu-used 8 -c:a libopus -shortest media/morning-clip.webm
ffmpeg -framerate 15 -i media/frames/closing/%03d.jpg -f lavfi -i "sine=frequency=262:sample_rate=48000:duration=6" -vf "fps=30,format=yuv420p" -c:v libvpx-vp9 -b:v 3M -deadline realtime -cpu-used 8 -c:a libopus -shortest media/closing-clip.webm
# TurboMusic: four short tones so tracks count as having audio (audio/t1.mp3 .. t4.mp3, i = 1..4)
ffmpeg -f lavfi -i "sine=frequency=$((110*i+90)):duration=40" -f lavfi -i "sine=frequency=$(( (110*i+90)*3/2 )):duration=40" -filter_complex "amix=inputs=2,volume=0.3,afade=t=in:d=1,afade=t=out:st=38:d=2" -ac 2 -b:a 96k audio/t$i.mp3
```

## Gotchas found while capturing
- **Look at every capture, in both modes.** An app that does not follow the device's colour scheme gives a "light" capture that is dark (TurboBudget keeps its own look: `budget.mjs` sets `turbobudget.appearance`). A palette id the app's pinned theme bundle does not know is silently ignored (`turbomusic-light` rendered dark).
- TurboKeep never reaches "network idle" (it holds a live connection), so wait for `load`, not `networkidle`. It waits to see whether a click becomes a double click: pause about a second after clicking a note.
- TurboBudget stores money with signs: withdrawals and the outgoing leg of a transfer are negative. Seed them positive and every expense shows as income. Many small categories make the pie chart's labels collide: keep about eight.
- TurboCut's timeline zoom is pixels per frame (`store.zoom`, default 3): about 1.5 fits a 14 second edit on a 1440 px screen. Media is imported with the bin's "Import files…" button and put on the timeline with each clip's "Add". In a dev checkout the app also shows an "update available" notice; wait it out.
- TurboDocs: slide text commits with Escape. A slide theme (Slide > Change theme) restyles every existing slide and **replaces slide backgrounds**, so create the slides first and apply the theme last; new slides do not inherit it. A picture goes in through the hidden file input (`setInputFiles`). In Sheets, Enter moves down only: press Home after a row to start the next one.
- TurboPantry's recipe pictures are uploaded with `POST /api/images` (raw bytes) and the recipe's `imageUrl` set to the returned `/images/...` path; the dev web server needs `/images` proxied or the cards show broken images.
- A dev server that binds IPv6 (`::`) fails on a machine without it: pass `--host 127.0.0.1`.
